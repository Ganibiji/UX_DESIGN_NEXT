Kestrel Design System · v1.0 · for Kestrel Business Suite (ERP + CRM)

Built for people who use it eight hours a day

Kestrel serves accountants, sales managers, buyers and warehouse operators. Every decision is judged by one question: does this help someone finish real work faster and with fewer mistakes? Visual polish follows from that — never the other way round.

1 · State before style

Users must always know what a record is, what state it’s in, and what happens next. Status, document flow and save state are always visible.

2 · Density with hierarchy

Show a lot, but rank it. Tables and forms are compact; type weight, alignment and whitespace — not boxes — create order.

3 · Calm by default

Neutral surfaces, one brand blue, colour only for meaning. If everything is highlighted, nothing is.

4 · Recoverable

Undo instead of “Are you sure?”. Confirm only what can’t be reversed, and say exactly what will happen.

Questions every screen answers

What is the user trying to do?Primary action is singular and visible without scrolling.
What matters most here?Key facts strip on records; KPIs before charts on dashboards.
How often is it used?Daily screens get shortcuts, saved views and compact density.
Beginner or power user?Labels always visible; shortcuts are additive, never required.
What if something goes wrong?Every state is designed: empty, error, partial, offline, no access.
Can it be done quickly?Inline edit, bulk actions, smart defaults, remembered filters.
Is the record’s state clear?Status + document flow + approval chain + audit history.
What happens next?Decision bars and “next step” menus name the next action.

Colour

Every colour is a semantic token. Components never reference raw hex values. Values below are read live from the current theme.

Brand & semantic

Rules

Do — use colour only when it carries meaning: status, validation, the one primary action, the current location. Pair it with a shape, icon or text.
Don’t — colour-code modules, rows or categories for decoration; use status colours for chart series; put coloured text on coloured fills without the “-text” token.

    Accessibility (WCAG 2.2 AA)

    ContrastText ≥ 4.5:1 in both themes (muted text 4.8:1 on page). Input borders ≥ 3:1. “-text” semantic tokens are tuned for tinted fills.
    Not colour aloneStatus markers have distinct shapes; row attention adds a rule and text; errors include an icon and message.
    FocusOne 2px ring everywhere via :focus-visible; inset in clipped areas; never removed. Focus returns to the trigger when overlays close.
    KeyboardMenus (arrows, Home/End, Esc), tabs (arrows), tree (arrows), grid (Enter/F2 edit, resize handles), Kanban (Alt+arrows — WCAG 2.5.7 alternative to dragging).
    Target size≥ 24px everywhere (2.5.8); touch devices force ≥ 36px even in Compact.
    FormsVisible labels, aria-required, aria-invalid + aria-describedby to the message, error summary with links, autocomplete tokens.
    TablesReal <table> with scope, aria-sort, labelled selection checkboxes, scroll region with a name.
    DialogsNative <dialog> showModal (inert background), labelled title, safe default focus on the non-destructive action.
    Live regionsToasts (status), selection count, save state; alerts only for errors that block.
    Motion & modesprefers-reduced-motion zeroes durations; forced-colors keeps borders; skip link; lang=en-IN.

    Architecture

    HTML + SCSS + CSS custom properties, no utility framework. Themes and density are attribute-scoped, so any subtree can switch. The React layer maps 1:1 to these class names.
